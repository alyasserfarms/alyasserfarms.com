# المراجعة البصرية والوظيفية

## أدلة المراجعة

راجع الواجهة في متصفح حقيقي عند توفر بيئة تشغيل وأدوات مناسبة. التقط الجوال والكمبيوتر بعد استقرار الخطوط والصور، ثم افحص اللقطات نفسها؛ نجاح البناء وحده لا يثبت جودة التصميم. عند غياب البيئة أو الأدوات اذكر القيد والخطوات غير المنفذة، ولا تُعلن اجتيازها.

نقاط بداية للمقاسات: 390×844 للجوال و1440×900 للكمبيوتر، مع اختبار ضيق عند 320 بكسل وعرض وسيط إذا ظهرت مشاكل انتقال. افحص الجزء الأول والصفحة الكاملة وتفاصيل عناصر التفاعل؛ لا يكفي تصغير لقطة كمبيوتر إلى حجم هاتف.

غطِّ الشاشات المنفذة في النطاق الحالي: الرئيسية والمتجر والمنتج والسلة والتوصيل ولوحة التحكم. لا تطلب بناء صفحات غير موجودة لمجرد استكمال قائمة المراجعة. أضف حالات مؤثرة مثل اسم منتج طويل، سلة فارغة، خطأ عنوان، عدم توفر منتج، وقائمة فلاتر مفتوحة.

## فحص اللقطة

- هل الاسم «مزارع آل ياسر» والشعار التسويقي «الخير له أصل» صحيحان؟ هل الشعار من `public/brand/` عند وجوده، دون إعادة توليد أو استبدال؟

- هل تبدو الهوية مرتبطة بـ The Living Farm من الصورة والتكوين والخط والإيقاع، أم مجرد لون أخضر فوق قالب عام؟
- هل الفعل الأساسي واضح دون منافسة؟ هل الأسعار والوحدات والكميات سهلة المقارنة؟
- هل العربية متصلة ومقروءة؟ هل اتجاه الأسهم والأرقام والعملات والمحتوى المختلط صحيح؟
- هل يوجد قص للنصوص أو انزلاق أفقي أو صورة مقصوصة بشكل يغيّر معنى المنتج؟
- هل التباين فوق فيديو الافتتاحية صالح عبر الإطارات، وهل الصورة البديلة مستقلة ومقروءة؟
- هل تتكرر البطاقات بلا غرض، أو توجد زجاجيات وتدرجات ممنوعة أو حركة تشوش الشراء؟
- هل صور المزرعة والمنتجات وادعاءات الثقة موثقة؟ هل الأصول التمثيلية واضحة في المعاينة؟

## التفاعل وإمكانية الوصول

استخدم أهداف WCAG 2.2 AA كمرجع قبول، ولا تصف نتيجة فحص آلي وحده بأنها امتثال كامل:

- قِس تباين النص العادي بهدف 4.5:1، والكبير 3:1، والعناصر البصرية الضرورية للمكونات والحالات 3:1 حيث ينطبق. افحص الحالات الفعلية والأخطاء والتركيز والنص فوق الصور، لا ألوان اللوحة منفردة.
- جرّب التنقل بلوحة المفاتيح والتركيز الظاهر وترتيبه؛ القوائم والحوارات تغلق وتعيد التركيز، دون حبس غير مقصود. افحص أن الأشرطة الثابتة لا تحجب العنصر المركّز.
- راجع الأسماء القابلة للوصول والتسميات والأخطاء وروابط المساعدة وإعلان تحديث السلة، مع اختبار يدوي لقارئ شاشة عند توفره. اجعل صور المنتج ذات بديل وصفي والصور الزخرفية متجاهلة دلاليًا.
- اختبر التكبير حتى 200% وإعادة التدفق بعرض ضيق. افحص أهداف اللمس وتباعدها، ولا تعتمد على hover أو اللون وحدهما.
- اختبر تقليل الحركة وإيقاف الفيديو وتعطّل تشغيله وفقد الصورة. لا تجعل الحركة شرطًا لفهم حالة أو إتمام عملية.
- جرّب مسار منتج → خيارات وكمية → سلة → عنوان وتوصيل → مراجعة إجمالي ضمن بيئة اختبار. لا تنشئ طلبًا فعليًا أو دفعًا خارجيًا دون تفويض مناسب.

## الأداء

قِس بيئة الجوال والكمبيوتر مع توثيق الأداة وظروف القياس والصفحة؛ ميّز اختبار المختبر عن بيانات المستخدمين الميدانية. أهداف أولية: LCP ≤ 2.5s وINP ≤ 200ms وCLS ≤ 0.1 عند المئين 75 من البيانات الميدانية إذا توفرت. لا تستنتج INP الميداني من لقطة Lighthouse أو TBT وحده.

راجع طلبات الشبكة وحجم الصور والفيديو والخطوط ومكوّن LCP، وثبات التخطيط واستجابة إضافة السلة. اختبر اتصالًا بطيئًا: يظهر العنوان والشراء والصورة البديلة سريعًا، ولا يُنزّل فيديو ضخم في وضع توفير البيانات أو تقليل الحركة. ضع ميزانية نقل واقعية للأصول بعد فحص المحتوى، وقارن قبل/بعد عند إجراء تحسينات؛ لا تدّعِ أرقامًا دون قياس.

## الإصلاح والتقرير

رتّب النتائج حسب الأثر: تعذّر الشراء أو الوصول، ثم فقد الوضوح والثقة، ثم الصقل البصري. أصلح داخل النطاق الموافق عليه، وأعد التقاط المقاسات والحالات المتأثرة. توقّف عند قيد يتطلب أصولًا أو بيانات أو موافقة جديدة، وبيّن أثره بدقة.

سلّم سجلًا موجزًا: الشاشة والمقاس والحالة، المشكلة، الإجراء، دليل إعادة الفحص، وما بقي غير متحقق. اربط اللقطات والقياسات الفعلية إن حُفظت. اذكر بوضوح إن كانت النتيجة خطة فقط ولم تُنفذ واجهات بعد.
