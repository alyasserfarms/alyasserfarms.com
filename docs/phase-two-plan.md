# المرحلة الثانية — واجهات التسوق

استكمال طلب «كمل» بعد عرض المرحلة الأولى: صفحات المتجر والمنتج والسلة والتوصيل، بنفس الهوية والتقنيات. لا قاعدة بيانات أو إدارة أو دفع أو طلبات فعلية. المحتوى والأسعار والصور التجريبية تبقى موسومة.

المتجر `/shop`: عنوان تحريري واضح، بحث وفئات وفرز، شبكة صور منتجات موحدة للمقارنة، حالة عدم وجود نتائج، وروابط مباشرة قابلة للمشاركة للفئات. المنتج `/products/[id]`: صورة كبيرة، سعر ووحدة واضحان، كمية وإضافة للسلة، ملاحظات البيانات التجريبية ومنتجات مرتبطة. لا مخزون أو شهادات أو سياسات مختلقة.

السلة `/cart`: قائمة قابلة للتعديل والحذف، إجمالي تجريبي، استرجاع آخر حذف، حالة فراغ، وحفظ معرفات المنتجات والكميات محليًا دون أي بيانات شخصية. التعامل مع تخزين محظور أو بيانات تالفة، ومزامنة التغييرات بين الصفحات والتبويبات. حد واجهة 99 وحدة لكل صنف لمنع إدخال كميات غير معقولة؛ ليس معلومة مخزون.

التوصيل `/delivery`: نموذج محلي باسم ورقم هاتف ومدينة وعنوان وملاحظات اختيارية؛ أخطاء مرتبطة بالحقول وملخص أخطاء يستقبل التركيز. تقديم البيانات يعرض مراجعة محلية فقط، دون إرسال أو حفظ عنوان المستخدم ودون اختيار رسوم أو منطقة خدمة أو موعد غير معتمد. حماية حالة السلة الفارغة.

الشريط والتذييل مشتركان، وروابط الرئيسية تعمل من جميع الصفحات. يتسع التخطيط لعمودين على الكمبيوتر وعمود واحد على الهاتف، مع ملخص واضح دون حجب المحتوى. الهوية والخط والشعار المعتمد والوسائط الموجودة تُستخدم دون تغيير الاتجاه البصري. لا سحب اتجاه جديد لتصميم صفحات ضمن النظام نفسه.

التحقق: بناء الإنتاج وTypeScript وESLint، مراجعة لقطات 1440 و390 واختبار 320، رحلة متجر → منتج → إضافة → سلة → تعديل → توصيل → مراجعة محلية. اختبار حفظ السلة بعد إعادة التحميل، الفرز والبحث والفراغ، التخزين التالف، رابط منتج غير موجود، حقول التوصيل والأخطاء، ولوحة المفاتيح. الحفاظ على عمل الصفحة الرئيسية.
